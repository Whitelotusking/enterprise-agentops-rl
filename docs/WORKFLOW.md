# 学习、开发与版本管理约定

## 每周节奏

- 学习官方文档与原理：5 小时。
- 核心代码开发：13 小时。
- 测试、Benchmark 和失败分析：5 小时。
- 文档更新、面试问答与复盘：2 小时。

每周开始：确定用户故事、最小可执行任务、验收指标和所需资料。每周结束：自动化测试、固定演示用例、失败/风险记录、提交 commit、形成简短周报。每项任务至少能由代码或测试证明。

## 提交与版本规范

- 推荐分支：`main`（稳定）、`feat/w01-api-foundation` 等周任务短分支。
- 提交消息建议：`feat(api): add health endpoint`、`test(retrieval): add relevance fixtures`、`docs(roadmap): mark W1 accepted`。
- 不将 `.env`、密钥、数据集下载件、日志、模型权重、显存快照或真实隐私上传到公开仓库。
- 完成 W10 后打 `v1.0.0` 标记；模型实验配置、数据划分与随机种子独立记录。

## 需求优先级

- P0：API、数据库、RAG 基线、Agent/MCP、权限与幂等、评测、Web 演示、部署。
- P1：细化观测、优化延迟、SFT。
- P2：GRPO、复杂多 Agent/长期研究扩展。

## 质量门槛

每个模块必须：有可追溯源码、有测试、错误能复现、无硬编码密钥、文档明确输入/输出、失败时产生可读错误。对于训练指标，应记录所有失败实验，不删除负面结果。

## 费用约束

- 优先使用现有 GPU；不保证某类显卡始终可用。
- 默认本地 Docker 部署，不申请收费域名、云数据库或长期在线的 GPU 容器。
- 训练阶段评估预计显存和 GPU 小时，超出每月 100 元额外预算则缩减训练规模而不是透支费用。
- 模型 API 若用于比较或调试，其花费必须单独记录。
