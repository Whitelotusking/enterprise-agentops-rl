# 12 周学习与开发路线

## 学习约定

- 周期：2026-10-26 至 2027-01-17；每周 20–30 小时（按 25 小时组织）。
- 时间分配：原理与官方文档 5h、开发实践 13h、测试/实验/错误分析 5h、技术复盘/面试 2h。
- 每周必须包含 **可验证的交付物**：代码、测试、指标、说明、Git commit。
- 采用指导式学习：先理解核心原理，自主完成模块，再使用自动测试和代码审查定位错误。不能仅粘贴不理解的框架代码。
- 第 10 周前 **不将后训练作为主线的前置条件**；第 11–12 周按可用 GPU 评估训练范围。

## W1 · 10/26–11/01 · FastAPI 工程起步

**核心知识**：Python 项目组织、uv、HTTP/REST、路由、Pydantic v2、FastAPI 依赖注入、同步/异步接口、错误码、pytest、Docker 基础。  
**练习**：`GET /health`，任务与知识文档资源的最小 CRUD，结构化 4xx 响应、基本输入校验，测试客户端。  
**交付**：`backend/app/`、`backend/tests/`、项目依赖及启动说明。  
**验收**：有效请求返回约定模型；缺失/非法参数受校验；测试自动通过；本地服务可启动；不得伪称项目已部署。  
**面试题**：Pydantic 与业务层校验如何划分？`async def` 里调用阻塞 API 有什么问题？FastAPI 的依赖注入解决什么问题？

## W2 · 11/02–11/08 · PostgreSQL 与数据接入

**核心知识**：表设计、PK/FK、JOIN、事务隔离、索引、SQLAlchemy 2、Alembic、连接池、幂等导入。  
**练习**：建 `tenants/users/documents/chunks/tasks/tool_calls/approvals` 基础表；导入仿真业务文档及元数据，并记录数据集来源、版本与哈希。  
**交付**：SQL 迁移、数据库模型、可重复运行的导入脚本、接口与数据库测试。  
**验收**：迁移可重复执行；唯一约束有效；事务回滚正确；重复导入无重复数据；重启保留状态。  
**面试题**：索引何时失效？什么是幂等导入？为何不能靠 Agent Prompt 保证数据权限？

## W3 · 11/09–11/15 · RAG 端到端

**核心知识**：解析/切分、Overlap、Embedding、pgvector、向量距离与索引、PostgreSQL 全文索引、引用溯源。  
**练习**：可重复的文档导入流水线；基础 Sparse/Dense 检索；返回文档来源、段落、文档版本、匹配分数。  
**交付**：`retrieval/` 模块、`POST /search`、数据库索引与测试数据。  
**验收**：检索结果含可追溯的 doc_id；失效版本可以过滤；空结果明确返回；租户标识贯穿到后端查询。  
**面试题**：Chunk 过长/过短的取舍？pgvector 的 HNSW 和精确搜索怎么比较？

## W4 · 11/16–11/22 · RAG 基线与评测

**核心知识**：Hybrid Retrieval、RRF、Cross-Encoder Rerank、Recall@K、MRR、nDCG、ANN 过滤与索引策略。  
**练习**：固定查询集、关联文档标注，比较全文、Dense、Hybrid+RRF、Hybrid+Rerank；测试文档版本与租户过滤。  
**交付**：可执行的 `evaluation/retrieval/`、查询集、指标 JSON/CSV、实验报告。  
**验收**：四个基线同用一个查询集与测试环境；记录 Recall@5、MRR@10、nDCG@10、P95；有失败实例分析；不预设提升幅度。  
**面试题**：为何 RRF 有时比简单拼接好？为何混合检索可能退化？如何验证 Reranker 是否真正有价值？

## W5 · 11/23–11/29 · LangGraph Agent

**核心知识**：状态图、ReAct 与 Plan-Execute、状态机、短期记忆/长期存储、上下文压缩、持久化 Checkpoint。  
**练习**：实现“理解任务—检索规则—规划—调用工具—验证”的主图；在模拟环境中执行多步骤任务。  
**交付**：`agent/` 与状态持久化方案、执行轨迹、确定性节点测试。  
**验收**：至少覆盖单轮、缺少信息、多工具、超时、重启五类场景；重启后按检查点安全恢复。  
**面试题**：为什么用 LangGraph 而非纯 ReAct 循环？Checkpoint 与 Memory 的区别？如何压缩长上下文而不损害关键约束？

## W6 · 11/30–12/06 · MCP 与业务工具

**核心知识**：MCP Server/Client、Tool Schema、权限判断、工具错误、人工确认、幂等键、操作审计。  
**练习**：封装 5–8 个模拟业务工具：`search_policy`、`get_account`、`get_transaction`、`check_eligibility`、`create_case`、`get_case_status`、`request_approval`、`update_case`。  
**交付**：`mcp_server/`、工具 schema、读写操作权限校验与集成测试。  
**验收**：非法参数拒绝；敏感写入需显式批准；重试不导致重复工单；记录 `task_id/tenant_id/tool_name/status`。  
**面试题**：Tool 与 MCP 有何不同？如何避免工具调用注入？Agent 崩溃后如何处理一个状态未知的写操作？

## W7 · 12/07–12/13 · 企业安全和可靠性

**核心知识**：身份认证、RBAC、数据库行级安全 (RLS)、租户隔离、死信与重试、幂等、超时、审计。  
**练习**：至少两模拟租户；跨租户越权测试；重复写入测试；工具返回失败和服务重启；为必要操作加入审批。  
**交付**：鉴权和策略模块、安全测试报告、模拟故障脚本。  
**验收**：预先定义的跨租户攻击测试全部拒绝；重复提交只产生一次有效业务变更；失败可诊断、可恢复。  
**面试题**：只在向量检索上加过滤足够吗？幂等性在数据库还是 Agent 层实现？审批是否可能被重试绕过？

## W8 · 12/14–12/20 · Agent Benchmark / Bad Case

**核心知识**：任务成功率、数据库终态校验、轨迹错误分析、Tool Call Validity、成本与时延指标、评测数据泄漏。  
**练习**：用固定状态初始化任务；设计独立 Verifier；将错误归为检索、规划、参数、越权、超时、最终状态不符。  
**交付**：`evaluation/agent/`、任务种子、报告和 Trace 浏览数据。  
**验收**：每个测试任务有初始状态、执行轨迹、最终状态和评分记录；结果可重复运行；无训练集与测试集混用。  
**面试题**：任务成功与回答正确有什么区别？如何避免 Reward Hacking？如何根据 Trace 诊断失败？

## W9 · 12/21–12/27 · Web 前端

**核心知识**：React、TypeScript、API 状态、SSE 流式显示、表格和指标图表、错误提示。  
**练习**：对话执行页、知识管理页、Trace 页、Benchmark 页。  
**交付**：`frontend/` 与前后端联调测试。  
**验收**：浏览器中完成一条多工具业务任务，可看到检索证据、审批、工具调用及最终结果；断连有处理策略。  
**面试题**：为何选 SSE 而非 WebSocket？如何关联一次请求与后端多段 Trace？

## W10 · 12/28–2027/01/03 · 求职可演示 V1.0

**核心知识**：Docker Compose、CI、日志观测、负载测试、性能剖析、README 技术表达。  
**练习**：一键运行、自动测试、至少两档并发负载测试、启动故障说明、录制 Demo。  
**交付**：V1.0 标记、部署文档、性能报告、架构图、演示录屏。  
**验收**：新环境按 README 可启动、成功演示端到端任务；测试日志留档；无密钥、真实客户信息、模型权重入库。  
**面试题**：系统性能瓶颈在哪？性能指标如何测量？为什么不用微服务或 K8s？

## W11 · 2027/01/04–01/10 · SFT / LoRA

**核心知识**：轨迹转样本、过滤成功轨迹、PEFT/LoRA、训练/测试隔离、训练超参数与评估。  
**练习**：收集或生成与公开测试任务隔离的轨迹；训练小规模模型进行结构化工具选择。  
**交付**：`training/sft/`、数据构造脚本、实验配置、训练与评测日志。  
**验收**：对 Base 与 SFT 在相同测试集上比较；记录环境、随机种子和资源开销；无测试答案泄漏。  
**面试题**：如何构造 Agent SFT 样本？为什么 SFT 好不代表多步任务成功率高？

## W12 · 2027/01/11–01/17 · GRPO / 实验与简历

**核心知识**：可验证 Reward、group-relative 优势、rollout、KL/clip、Reward Hacking、消融实验。  
**练习**：若 GPU、正确性和时间条件允许，对小模型运行 GRPO，比较 Base、SFT、SFT+GRPO；不满足条件则完成可复现的最小实验与资源限制分析。  
**交付**：`training/rl/`、实验报告、简历项目描述、问答稿。  
**验收**：所有成绩来自真实实验；训练输入与基准测试集隔离；失败和无收益结论同样保留；不得将单纯的离线评分称为 RL 训练。  
**面试题**：GRPO 的优势如何构造？为何要控制策略分布偏移？如何设置任务级奖励与工具安全约束？

## 完成优先级

- **P0（必须）**：W1–W10、真实可演示系统、系统测试、RAG 与 Agent 评测。
- **P1（争取）**：W11 小模型 SFT 和指标对比。
- **P2（条件）**：W12 完整 GRPO、多种训练配置和更大规模消融。
- 如果任何阶段超时，先减少前端视觉细节、工具数量或模型训练次数，**不取消权限、幂等、数据隔离和评测**。
