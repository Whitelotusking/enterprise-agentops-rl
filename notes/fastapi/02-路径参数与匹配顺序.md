# FastAPI 02：路径参数和路由匹配顺序

来源：[FastAPI 中文教程：路径参数](https://fastapi.tiangolo.com/zh/tutorial/path-params/)  
整理日期：2026-10-26

## 一句话记住

**`/users/me` 是固定路径，`/users/{user_id}` 是动态路径；当二者可能匹配同一个请求时，先声明固定路径，再声明动态路径。**

## 示例

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/users/me")
async def read_user_me():
    return {"user_id": "the current user"}

@app.get("/users/{user_id}")
async def read_user(user_id: str):
    return {"user_id": user_id}
```

| 请求 | 命中哪个路由 | 返回结果 |
|---|---|---|
| `GET /users/me` | `read_user_me` | `{"user_id": "the current user"}` |
| `GET /users/123` | `read_user` | `{"user_id": "123"}` |
| `GET /users/zhangsan` | `read_user` | `{"user_id": "zhangsan"}` |

`{user_id}` 表示**从 URL 中提取变量**；`user_id: str` 表示该值按字符串处理。

## 为什么顺序重要？

如果把动态路径 `/users/{user_id}` 写在最前面，访问 `/users/me` 会**先匹配动态路由**，此时 FastAPI 把 `"me"` 作为 `user_id`，就到不了后面定义的专用 `/users/me`。

不要假设“写得更具体”就会自动优先。FastAPI 按已注册的路由顺序匹配。

**常见坑：** 即便参数写为 `user_id: int`，动态路由也会先匹配 `me` 这个路径，随后在参数验证时报错；它不会因为无法转换为整数而自动跳到后面的固定路径。

## 对应项目例子

```python
@app.get("/tasks/latest")
async def latest_task():
    return {"task_id": "T100"}

@app.get("/tasks/{task_id}")
async def get_task(task_id: str):
    return {"task_id": task_id}
```

应将 `/tasks/latest` 写在 `/tasks/{task_id}` 之前，避免将 `latest` 误当成任务编号。

> 这一节需要记住的只有两个点：**大括号代表路径变量；可能冲突时固定路径优先声明。**
